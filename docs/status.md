# 项目状态

更新：2026-10-25。当前工程采用伙伴交接包 `IMU_NODE_CLEAN` 的固件与电脑端实现，取代此前 USB、BLE、Wi-Fi 三套重复工程。它已经整合 USB 和 Wi-Fi 数据采集；单节点开发台与多节点旋转监控仍有各自的运行入口，共用协议、坐标和姿态模块。

## 当前做到哪里

| 阶段 | 已有实现或依据 | 尚需验证 |
| --- | --- | --- |
| 电路与硬件 | ESP32-S3、ICM-42688-P 六轴、LIS2MDL 磁力计；已有板子与固件引脚配置 | 后续硬件变更时重新核对原理图与实际接线 |
| 单板有线 | USB 串口采集；单节点页面有端口选择、实时姿态、记录和回放 | 在当前电脑和实际板子上重新确认设备、串口与动作响应 |
| 单板 Wi-Fi | 伙伴包保存了 2026-10-25 热点关联、TCP 接收及页面接口的真实记录 | 网络名称、地址和服务状态以当前现场为准 |
| 双板 Wi-Fi | 伙伴包保存了 A/B 并发接收与独立姿态计算的真实记录 | 完整物理转动、停止、再次转动的效果和长期动态误差 |
| 三板及更多节点 | 已有一至三路旋转监控和三节点实验预设软件 | 第三块板实测、跨设备同步、安装标定及扩大节点规模 |
| 数据处理与可视化 | 坐标映射、互补姿态融合、静置校准、停稳保持、磁场检查、记录回放 | 完整磁标定、动态精度、人体骨架与关节角验证 |

BLE 未纳入当前运行工程。当前路线为单板 USB → 单板 Wi-Fi → 多板 Wi-Fi；旧 BLE 实现不能视作本工程已验收的能力。

## 当前运行入口

| 用途 | 入口 | 默认页面 |
| --- | --- | --- |
| 单板 USB 或 Wi-Fi，记录与回放 | `host/run_dashboard.py` | `http://127.0.0.1:8000/` |
| 一至三板 Wi-Fi，相对旋转显示 | `host/run_wifi_monitor.py` | `http://127.0.0.1:8010/` |
| 三节点离线演示、显式实测采集与报告 | `host/run_motion_presets.py` | 输出独立 HTML 报告 |
| 同一份采集固件 | `firmware/platformio.ini` | A 热点环境与 B 客户端环境 |

每块板的 TCP 服务目前只接受一个接收程序。8000 开发台、8010 监控、直接接收脚本和预设采集不能同时连接同一板。

## 证据怎么读

- [单节点验证](validation/single-node.md)：12 秒直接 TCP 记录 1181 帧，约 98.3 Hz；该段无无效帧和序号缺帧。
- [双节点验证](validation/dual-node.md)：约 20 秒区间，A/B 分别新增 1876/1900 帧；两路均无新增序号缺帧和无效帧。
- [旋转稳定性验证](validation/rotation-stability.md)：静置校准后约 12 秒显示姿态最大变化约 0.125°/0.091°，含停稳保持作用。
- [实验预设](experiments.md)：合成输入和模拟流用于软件回归，三节点人体实验尚未完成。

以上实板结果均来自伙伴包的历史记录。本次目录整理不重新烧录、不连接硬件，也不据此认定当前现场已经复现。软件检查与历史实板证据分别报告。静置显示变化不能当作动态旋转精度；纯 IMU 位移积分仍会漂移。

## 后续顺序

先在当前电脑复现一块板 USB 与 Wi-Fi 的实时姿态，再复现 A/B 两路并发接收及转停动作。第三块板接入后，先做同刚体旋转检查，再做有外部角度参考的简单关节实验。更大规模节点、真正的跨设备时间同步和全身骨架属于后续开发。
