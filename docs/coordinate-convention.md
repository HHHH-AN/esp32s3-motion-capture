# 坐标与网页投影约定

更新：2026-10-26。人体世界系统一为右手 FLU：+X 人体前方、+Y 人体左侧、+Z 上方，X×Y=Z。屏幕左右不是人体左右。默认相机位于人体右前上方，面向人物，人物右臂通常显示在画面左侧。橙色仅表示选中，不代表左右。

## 完整链路

1. 固件 IMU2/IMU3 保持芯片库输出：ICM 加速度/角速度使用其本地轴；LIS 磁场使用其本地轴。USB 与 TCP 发送同一帧，不对某个传输取反。芯片轴与 PCB 朝向、两芯片相对安装均须依据器件和实际 PCB 核实，不能凭 USB 口或屏蔽罩推定。没有改固件字节或现场板卡。
2. 主机 sensor_axes 是明确的原始轴到融合传感器轴映射；只接受行列式 +1 的 24 种有向排列，拒绝单轴反射。它作用于 accel/gyro/mag。当前共同映射不能补偿两芯片之间尚未确认的独立安装差异；磁场轴对齐未实测时，磁参与不能算已验收。
3. 融合采用主动 sensor-to-fusion-world、wxyz 四元数及右手正角。每板融合世界不是天然共享的人体朝向。
4. 安装/方向标定用中立重力和明确向前抬臂辨识每板变换，骨段 R=A Q M。人体前举绕 -Y，右侧举绕 -X；子局部姿态 inverse(Rparent)*Rchild。功能标定不消除漂移。
5. 骨架左肩 anchor Y=+0.22，右肩 Y=-0.22；中立手臂向 -Z，脚尖向 +X。未测骨段保持局部零姿态。
6. 所有网页（固定/平移火柴人、板状节点、旧单板位姿、Wi-Fi 诊断）共用 pose_math.js 的相机投影。camera right × up = toward-camera，行列式 +1。仅在最终 Canvas 像素转换时翻转纵坐标，不反射世界或模型。
7. 旧 displacement_signs 继续作为独立实验位置修正以兼容记录，不再乘到模型姿态几何。页面明确标注为实验位移符号。它不定义人体坐标；旧记录保存的姿态/位置不重算，但旧网页镜像外观被修正。

## 已发现和修复

旧骨架投影从人物背面下方观察却缺少清晰前后说明，与旧单板/板状视图采用不同的投影基；旧单板轴符号更可直接产生行列式 -1 的模型反射。不能据此声称所有后端运算原本都是左手系。现在统一使用正交右手相机、上方视角和人体方向标识，删除模型几何的显示反射。没有按设备 ID 翻转数据。

## 离线与实板验收

Node test_scene_coordinates.js 覆盖多视角正交性、行列式、屏幕纵轴、人体左右、前举和侧举符号、旧负位移符号不镜像姿态，并执行三类真实画布绘制路径。Python 全套验证融合/标定/骨架/记录兼容。浏览器证据另见代码交接。

物理轴确认仍需用户逐步执行：单板依次朝向已知方向，检查重力与右手正旋转符号，再确认磁力计相对 IMU 轴。当前没有做这项实测，不据网页修复宣称硬件坐标已经验证。
