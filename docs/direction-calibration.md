# 安装与人体方向标定

更新：2026-10-26。本次直接修改现有 8000 开发台，没有创建隔离 baseline、提交或推送 Git，没有连接、断开、校准或切换真实设备。首次使用新后端需由用户在合适时机重启服务；本次没有停止既有 8000 服务。

## 确认的代码缺陷与未确定因素

原中立初始化保存 `Q0`，但 `fusion_to_world` 为单位四元数，实际骨段世界变换为 `Q Q0⁻¹`。若真实人体旋转为 R、固定安装旋转为 C、每板独立融合参考为 F，则 `Q = F R C`、中立 `Q0 = F C`，归零后的结果是 `F R F⁻¹`。它在中立时为单位旋转，却仍把动作轴转到了该板自己的融合世界系，因此“都归零、独立驱动正常”不保证人体前举/侧举方向正确。

该缺陷已用已知真值复现并修复。它能解释用户现象，不足以认定 A/B 的全部实板问题都只有这一项原因；当前没有读取真实服务或采集本轮实板证据。变化的陀螺偏置、融合参考漂移、磁场影响、实际佩戴和动作是否符合约束，仍需实板逐项排除。没有按 A 的设备 ID 取反、采用观测到的航向作为修正常量，或翻转整个场景。

## 两次定姿的数学条件

内部保持右手 X 向前、Y 向左、Z 向上、wxyz 主动旋转，乘积 `a*b` 先作用 b 再作用 a。先做已有的传感器轴映射，再使用映射后的融合四元数、加速度和扣除已接受零偏但尚未做停稳清零的角速度。

当前采用两次稳定姿态采样，生产算法版本为 `gravity-two-static-poses/3`（含轻微晃动容忍）、结果格式 `functional-installation/2`、会话格式 `body-direction-session/2`。中立时两段伸直自然下垂，重力给出 `C⁻¹ Z`。之后保持躯干不动、肘伸直、无附加扭转，向约定正前方抬臂停稳，采第二次姿态 Q1。其相对旋转为：

`D = Q0⁻¹ Q1 = C⁻¹ Rot(-Y, θ) C`。

对于正向、小于半周且幅度足够的前举，四元数主对数的符号给出 `C⁻¹(-Y)`；与中立重力这两个不共线向量可确定 C，无需把 θ 设成 30°或90°，也不使用设备ID或初始航向修正常量。两次静止窗口分别平均后计算，不能退化成单姿态归零。

拟合后保存并应用 `A = C Q0⁻¹`、`M = C⁻¹`，骨段姿态为 `R=A Q M`。当前求解器根据 reference 和 A 推导 M，其结果与显式 M 一致。父子局部姿态仍为 `R_parent⁻¹ R_child`，不相减欧拉角，不重复乘父旋转。右臂前举朝 +X、外侧举朝 −Y；两者分别绕 −Y 和 −X，因此可以用未参与拟合的侧举检查方向区分。

这里的“正前方、肘伸直、躯干不动”是操作者提供的外部约束，系统不能仅凭 IMU 知道你实际上把哪边叫前方。只有静站不能辨识任意安装航向；在上述约束成立时，不强制增加第二个拟合动作。检查静止、幅度、转轴与重力非退化、重力和姿态一致性，以及两段的终态幅度一致性；失败必须重采；两次端点无法核实中间路径，也不能排除所有航向漂移或确认肘是否在全程伸直；动作约束必须由用户遵守，之后用侧举、再次前举和独立屈肘验证。若需放宽约束，应另加独立观测，不能猜测一个解。

上述旋转组合顺序与双向量对齐的数学约定核对了 [SciPy 旋转组合](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.__mul__.html) 和 [向量对齐说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.align_vectors.html)。本工程用独立纯 Python 实现，不新增 SciPy 运行依赖。

## 在同一开发台如何操作

以下是完整流程说明；实板指导时仍一次只执行一步，确认结果后继续。

1. 在端点身份下方的“安装与方向标定”明确勾选本次设备，核对设备 ID、角色、当前模式、残余角速度、停稳状态、磁场是否参与及数据年龄。当前引导支持上臂/前臂/手，可单节点或同侧多个节点；不能给头、骨盆或腿套用手臂动作后声称已标定。手部传感器须固定在手背；中立和前举两次采样都保持手腕中立，手长轴与前臂对齐、作为整体前举。若已存在本轮中立数据或候选，设备范围会锁定；先点击“结束本轮并调整设备”，等待服务确认后再勾选。结束本轮保留已应用的标定，重新采中立才撤销所选设备旧参考。
2. 如需静置陀螺零偏校准，先逐板显式执行并等待质量通过。它与安装/方向标定和磁标定分开；A 若再次出现静止大角速度，应先处理该问题，不能靠方向标定吸收变化偏置。
3. 明确人体前方；身体或两段结构保持稳定，上臂与前臂伸直自然下垂。点击“采样中立姿态”后先有2秒准备时间，再自动寻找约1.3秒稳定数据；轻微自然晃动允许，不要求绝对静止。服务端最多等待15秒，未稳定时显示具体原因并继续寻找，无需反复点击。新采中立即撤销旧参考；不需要再点击停止。
4. 保持肘伸直，向人体正前方抬臂，再点击“采样前举姿态”，同样先准备再等待稳定窗口。姿态检查通过后自动结束；不用放回，也不用手动摆准角度。准备及等待数据留作证据，但只有选定的稳定窗口参与拟合。
5. 候选通过后点击“应用标定结果”。失败时按中文提示重采；不静止或幅度太小可重采前举，身份/参考变化或两段不一致则重采两次。不要随后点击“仅中立归零”，它会撤销方向标定。
6. 应用后分别验证侧举、再次前举和上臂稳定时独立屈肘。前臂/手组合还须验证前臂保持稳定时独立屈伸腕，手部仅相对前臂转动；未测量手部仍只按层级随动。这些是方向与几何验证，角度精度仍需外部真值。

配置仍集中于 `host/config/direction_v1.json`，为保持旧分析接口保留原往返阈值。生产流程先准备2秒，每0.25秒检查最近约1.3秒的共同窗口，总等待上限15秒；多个设备须在同一时间区间稳定，不拼接不同时间的姿态。窗口角速度平均向量模长≤3°/s、中位模长≤12°/s，单帧峰值超过15°/s仍拒绝该窗口。手持往返微动可出现约10°/s瞬时角速度，仍须满足姿态波动和平均角速度条件，不等于允许持续10°/s转动。最多排除5%的瞬时异常（角速度>12°/s、重力模长越界或姿态偏离均值>3°），保留原始数据及排除索引；无效帧、身份变化和时间缺口不按噪声剔除。剩余数据至少0.8秒/20帧，姿态最大波动≤3°、加速度模长0.85–1.15g、波动≤0.04g。持续转动或明显偏置、反复晃动仍无法通过，需按提示放稳或另做零偏校准。

两姿态差幅度15°–150°、转轴竖直分量≤0.25、重力一致性误差≤6°，同时标定同侧上臂/前臂时终态幅度差≤12°，这些几何条件未放宽。前臂/手的腕中立由操作者保证，当前没有专门的腕部双段一致性门控，不声称系统已确认手腕姿势。幅度下限为可辨识门槛，不是目标角度。两次稳定端点不核实中间动作路径、回位或运动积分；时变航向仍可能污染端点。

页面采用“连接 → 端点身份 → 详细检测与标定并排 → 骨架/板卡 → 记录回放”。小屏自动纵排，坐标/实验位置/曲线默认折叠。滚轮用于页面滚动；各模型下方有缩放滑条，拖动仍可旋转相机。命令按钮有等待与服务端确认反馈，重复提交受保护；确认仅代表请求处理完成，真正的采样和校准状态以所在面板为准。超时提示结果未确认，不自动重试。

设备采样时钟展开后用于窗口间隔，保留实际主机到达时间并按窗口锚定到主机时间；避免 Windows 粗粒度时钟让不同帧拥有相同到达时刻。仍为软件时间对应，不是硬件同步。

## 模式、漂移与失效

保留已有六轴相对模式和磁场质量门控模式，可由用户逐设备显式切换进行受控比较；本向导不会自动切换真实板卡模式，也不保证统一成六轴就解决所有方向问题。切换模式或算法重置会撤销相关方向标定，需重做中立与前举。残余角速度使用停稳前观测，画面停住不能作为零漂证明。

换板、重启/时钟重置、换角色、轴映射、重新佩戴/换人、融合参考/算法或零偏改变时，原变换保留为无效历史、实际 A 清回单位旋转、reference 撤销，不能继续驱动为已标定。采集中遇到断线、数据年龄超过 250 ms、坏帧、序号缺帧、采样间断、冲突或签名变化会拒绝，不能静默跨越。回放和录制时不可改标定；采集窗口期间也不能开始录制/回放。功能标定只处理固定坐标变换，不能消除时变航向漂移。

## 保存与回放

每次中立检查、拟合、应用或失败的采集证据自动保存在 `host/recordings/calibrations/*.json`，不会自动在下一次启动时套到设备上。保存 schema/算法/配置版本、设备/角色/启动会话/处理模式/坐标签名、参考及 C/A/M、完整采集窗口、实际选用的稳定窗口、异常值排除索引、原始与扣偏角速度、质量/拒绝原因及内容哈希。证据后台写盘，保存失败明确报错。

正常动作会话继续使用 `host/recordings/<session>`。开始录制时将完整标定证据一次性存入 metadata 快照；采样关联 calibration_id，骨架帧保存当时变换、有效性和标定结果，避免每个显示帧重复塞入原始动作窗口。默认回放读取保存的姿态与标定；新算法重算需另作分析。旧 IMU2/IMU3、旧会话、单板、多端点、冲突隔离和缺失段局部零姿态兼容保留。

## 初版两次定姿检查及历史结果的边界

本轮按用户要求移除了8000页面的无硬件分层测试、方向模拟设备/动作及模拟位置入口，没有新增虚拟硬件、演示场景或测试页面。底层历史测试辅助和旧往返拟合函数保留，供显式离线分析；生产向导调用 `fit_static_direction`，旧录制默认仍重现保存帧，不重新拟合。

本轮仅做 Python AST/JSON、页面结构/唯一ID/控制器DOM引用/模拟入口移除/滚轮监听移除检查、JavaScript语法与少量现有前端检查，以及3项独立定姿数学单元检查。没有运行大规模模拟、全套回归、浏览器自动化或截图；没有读取、重启8000或操作真实板卡。现有集成测试的采样辅助已适配定姿契约，本轮没有运行其硬件替身链路。

此前完整往返版本的215项回归和Chrome记录回放结果属于历史，见 [历史方向验证](validation/direction-20261026.md)，不能当作当前两次定姿或新版布局已实板通过。当前静止采样时序、前举/侧举/屈肘效果、页面舒适度、滚动/按钮反馈及新标定记录回放均待用户实测。方向标定不等于漂移消除或角度精度验收。
