# 十四槽位姿态软件基线

> 当前使用提示（2026-10-26）：8000页面已移除下文历史描述的模拟/分层测试入口，详细检测与方向标定已上移。当前安装向导为[两次定姿采样](direction-calibration.md)；下文保留软件基线阶段的实现背景，不作为当前模拟按钮操作指引。

本版直接实现在当前工程，没有创建隔离 `.codex/baseline`，也没有待复制的迁移步骤。这遵从本次用户最后的实施指令。运行入口仍为 `host/run_dashboard.py`，默认页面 `http://127.0.0.1:8000`；没有另一套火柴人开发台。

## 伙伴算法整合后的校准

`host/config/attitude_v1.json` 定义独立于身体位置的处理策略。默认使用磁场质量门控，并在没有可信磁场观测时使用伙伴的重力向量倾斜校正。按包内明确物理 ID，A=`imu_305A6077C398` 默认六轴相对姿态，B=`imu_149B6077C398` 默认磁场门控；未知设备不按 IP、COM 或身体槽位猜策略。页面“选中设备融合策略”可作本次运行的显式覆盖；策略及配置哈希进入会话。

伙伴原轴映射 `-X / +Y / -Z` 仅保留为核对信息，没有自动覆盖本机身体配置或已选设备映射。实际安装和坐标方向仍需现场确认。六轴模式保留磁场原始显示，但不将其用于航向；不能据此获得可靠长期绝对航向。旧欧拉互补配置仅供离线对照。

选中有有效原始采样的设备后，静置零偏校准先等待约 0.8 秒放稳，再采集至少 4 秒、至少 200 个有效样本。不稳定时重新等待并自动重试，整次最长 30 秒；可用“取消零偏校准”停止，原有成功零偏保留。逐轴标准差上限 0.45°/s、首尾均值变化上限 0.25°/s 属于当前启发式阈值；磁场随机噪声由航向质量门控处理，不单独阻止零偏平均。磁场方向趋势、明显运动和采样时间中断仍受检查。

零偏校准开始、完成、融合策略改变或设备时钟回退都不能复用旧安装参考；完成后再使用中立站姿引导。初始化静止检查会扣除已接受的零偏，不把稳定零偏误判为运动。“校准后停稳保持”可关闭以观察慢动作，关闭不取消零偏补偿。停稳是阈值假设，可能漏掉极慢运动；归零不等于消除漂移。

记录或回放时禁止切换处理策略、校准或修改停稳开关；回放显示保存时的姿态和算法信息，不用新算法重算旧会话。完整整合证据见 [伙伴算法整合](validation/partner-drift-20261025.md)。

## 可以验证的链路

USB / Wi-Fi 端点 → 协议解析 → 设备身份与身体位置 → 每设备独立融合、时钟和质量 → 中立站姿参考 → 层级骨架 → 三类视图与选中设备诊断 → 完整帧记录和回放。

页面上方保留原连接操作，可为每路填写不同端点名称并单独断开。IP、COM 和端点名称都不是物理设备身份。同设备 USB/TCP 双路只接纳选定的主来源；另一条来源隔离并计数，可显式切换主来源，切换后须重新初始化。两个设备绑定同一身体位置时，两者隔离，不以最后到达者覆盖。匿名十一列旧 CSV 无可信物理身份，只以 `legacy:<endpoint>` 暂存诊断，必须显式绑定，且应只连接同一板的一条传输；不能凭地址自动识别两条匿名流来自同一板。

三个视图共用同一个 `body_frame`：固定根部只看姿态；可平移视图额外叠加独立位置来源；各设备视图展示各自板状模型及坐标轴。拖动/Shift 拖动/滚轮仅控制相机。独立位置来源默认关闭，可输入明确标识的模拟位置，或显式启动实验性惯性估算；后者会漂移，不是可靠绝对定位，不影响固定根部视图。

槽位列表、骨段点击和设备选择联动；选中节点下方显示原始三轴、温度、姿态、曲线、序号、缺帧/重复/坏帧、数据年龄和零偏/磁场质量，展开诊断可检查设备会话、参考和版本。异常样本拒绝并计数，不通过平滑补成真实采样。

## 配置和数学边界

`host/config/body_v1.json` 集中定义槽位、中文名、父子关系、默认骨长、连接偏移、佩戴提示、中立姿势、时间和初始化阈值。十四个规范骨段为 pelvis、head、左右 upper_arm / forearm / hand / thigh / shank / foot。历史 shoulder / elbow / wrist / hip / knee / ankle 只在明确启用 `historical-slots/1` 映射时兼容，不由名字推断实际安装位置。手、足的独立测量要求传感器固定在手背、脚背等对应刚体。

可复制配置后手工调整骨长、节点数量或拓扑，用 `host/.venv/Scripts/python.exe host/run_dashboard.py --body-config <配置文件路径>` 启动；配置须父先子后且只有一个根。修改后重新初始化，不凭 IMU 自动测骨长。网页默认使用十四布局，模拟数量选择覆盖 1、3、14 个节点。

统一使用右手 X 向前、Y 向左、Z 向上、wxyz 四元数。融合、轴映射、融合参考到人体世界的固定旋转、安装参考与渲染分离。骨段世界姿态为 `A Q M`，初始化取 `M = inverse(Q0) inverse(A)`；子段局部姿态为 `inverse(Rparent) Rchild`，不相减欧拉角，也不重复乘父旋转。未接入段局部旋转为单位四元数，仅因父段而随动；失鲜/断线保持最后局部姿态并告警，缺失链标记降级。

本布局以骨盆代理胸廓，没有独立胸骨盆扭转、肩胛、脊柱或手指测量。中立参考不证明各板拥有相同可信航向：仍依赖共同站立朝向和约定的佩戴方向，后续可增加功能动作标定。没有精确解剖关节角验收。

`body_nodes.FusionProvider` 是队友算法替换边界：每设备一个 provider，`update(sample, correction_scale)` 返回传感器到融合参考系的右手 wxyz 旋转，`reset()` 撤销内部状态，并提供 `version`。更新算法、融合参考重置、设备重启、配置/角色变化、换板、换人或重新佩戴，都必须明确撤销安装初始化。用户可重新确认绑定或使用“重新佩戴 / 重置参考”后再次初始化。不要直接替换成已归零但未声明坐标含义的四元数。

## 无硬件复现

1. 在仓库根运行 `tools/start_dashboard.ps1`，打开 8000 页面；不点击真实连接。
2. 在“无硬件分层测试”选择“已知姿态 → 骨架”，选择节点数、骨段、轴和角度，点击加载。模拟和硬件有效数分开；未提供数据的骨段保持局部零姿态。相同路径/数量/骨段/轴下更新角度会保留模拟会话，用于独立旋转检查。
3. 选择“模拟原始传感器 → 处理链”，加载后先核对绑定，再点击初始化引导、按目标姿势约定、点击确认。确认后采集新的静止窗口：默认至少 1 秒、20 样本，检查角速度、重力和姿态变化。目标图仅供引导，不覆盖真实数据；页面给出完成/失败与节点范围。初始化后更新同一模拟配置的角度可验证融合与映射；改变路径、数量或角色会重建模拟会话并要求重新初始化。
4. 点击开始记录，停止并保存，在会话列表选择、加载、播放/暂停/拖动时间，最后返回实时。新会话位于 `host/recordings/<session>`。记录中不能改绑定、参考、校准或模拟配置；回放与记录互斥。回放期间实时采集可继续，但只有保存的帧驱动骨架。

初始化的“姿态/安装参考”、静置陀螺零偏校准和磁标定是不同操作；归零不消漂、不自动启动位移。零偏校准会撤销安装参考，完成后重新初始化。尚未实现完整硬铁/软铁磁标定。

录制格式 `imu-body-session/1` 包含 `samples.jsonl`（原始和映射后测量、融合四元数、时序和身份）、`body_frames.jsonl`（实际驱动骨架和位置/诊断）、`events.jsonl`、`metadata.json`（骨架/骨长/坐标/绑定/参考/算法快照）及 `frame_index.jsonl`。长记录按稀疏索引流式读取，不用旧约 5000 点抽样预览充当动作回放。默认重现保存帧，算法重算另做分析；文件写入失败或队列满会停止并标 incomplete。会话下载接口为 `/api/body/recordings/<session>/download`，不保存 Wi-Fi 密码。旧 CSV 预览和接口保留以读取历史资料，不是新版完整动作会话。

可重复运行全链离线负载检查（不会打开串口或 TCP）：

```powershell
host/.venv/Scripts/python.exe -B -X utf8 tools/check_body_pipeline.py --nodes 14 --seconds 8 --record
```

此命令的模拟运行数据也保存在 `host/recordings`。CPU/样本/处理耗时只反映当前电脑的软件链路，不测无线吞吐、采样到屏幕延迟或动作精度。

## 单板接入准备与固件配置

已在板上的 IMU2 流无需为了软件试用立即重烧；连接后先显式绑定一个身体骨段，再做中立初始化。其他十三槽位不自行推测动作。当前设备/端口需重新确认，不能沿用历史 COM7。

同一固件通过 MAC 保留 `device_id`，独立上报 `body_slot`、随机 `boot_id`、固件及配置版本。IMU3 为：`IMU3,id,body_slot,boot_id,firmware,config,sequence,device_us,flags,<11个原始值>`，共 20 列；继续兼容 IMU2 / 十一列 CSV。默认角色 unassigned，不默认右腕。网络 A/B 构建环境与身体位置正交，B 的固定地址不因位置改变。

包装器使用真实 PlatformIO 构建参数，不添加不存在的 `--body-slot` 选项。可先只预览，不写配置、不编译、不上传：

```powershell
tools/build_node.ps1 -BodySlot left_hand -Environment esp32-s3-devkitm-1 -DryRun
```

编译时去掉 `-DryRun`；上传另需显式 `-Upload -Port <当次确认的端口>`，本轮未执行。包装器生成本地 `firmware/include/node_config.h`，配置版本包含布局/角色哈希；此文件真实参与头文件依赖，配置变动还会清理选定构建环境再重编。现有用户自写配置须显式指定替换才能覆盖；Wi-Fi 私有配置和环境的 build_flags 保留。可用 `-ProjectDirectory M:\firmware` 使用已核实的现有映射，工具不自动建立/撤销映射，也不修复全局 PlatformIO。
