## 实时观察

原测试时监控按 A/B 配置运行于 http://127.0.0.1:8010/ 。测试后恢复了原 Wi-Fi `sdu_net`。重新观察时需启动当前监控、保持两块板供电，并让电脑加入实际 ESP32-IMU 网络；程序随后尝试重连两块板。热点无 Internet 不影响本机页面，当前服务是否运行仍应实际检查。

重启监控：

```powershell
.\tools\start_wifi_monitor.ps1
# 或：
python -B -X utf8 host/run_wifi_monitor.py --node A=192.168.4.1:9000 --node B=192.168.4.201:9000
```

将两块板放到参考姿态，可分别点击 A/B 的“参考姿态归零”，再分别转动检查模型响应。归零只设置显示参考，不执行陀螺零偏或安装标定。A 是本次网络中心，观察期间必须持续供电。一个节点当前只接受一个 TCP 客户端，不要再同时启动其他接收程序占用相同端点。

重复真实并发验证时，应先启动双节点监控，然后运行：

```powershell
python -B -X utf8 tools/check_wifi_node.py --monitor-url http://127.0.0.1:8010/ --monitor-node A=192.168.4.1:9000 --monitor-node B=192.168.4.201:9000 --seconds 20
```

验证工具使用已保存 Wi-Fi 配置，不读取密码；有独立恢复守护，并在测试后恢复原网络。第三节点后续可使用另一独立地址加入 A，但必须另行烧录和实测，不能由本轮双节点通过推断三节点通过。
