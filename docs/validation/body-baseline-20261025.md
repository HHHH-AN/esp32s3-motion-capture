## 十四路离线负载

命令：`host/.venv/Scripts/python.exe -B -X utf8 tools/check_body_pipeline.py --nodes 14 --seconds 8 --record --report .codex/reviews/body-load-20261025.json`。

- 输入是十四路合成原始样本，目标每路 100 Hz，共 8 秒。
- 接收/处理 11200 / 11200 样本，坏帧 0；记录 11200 样本、241 个骨架帧、29 个事件，写入错误为空，末帧可回放。
- 本次批处理耗时中位约 1.81 ms、p95 约 4.92 ms；包括十四路处理，以及部分轮次的骨架快照和记录入队。不包括无线和采样到屏幕的全链延迟；不是保证阈值。
- 硬件在线计数为 0。会话 `host/recordings/20261025-211009-body-514b0568`，来源标记 `simulation_sensor`；不能据此宣称十四板吞吐、长稳或网络验收。

## 浏览器交互

使用 Playwright CLI 驱动 Chrome，测试服务仅监听本机回环 `127.0.0.1:8765`，没有代替用户连接硬件。检查了：

1. 十四路已知姿态的三类视图、十四槽位、模拟/硬件分开计数，以及列表选择联动。
2. 将左前臂模拟设备临时绑定到已有 head：head 显示两设备冲突且 measured=false，持续输入不会自动把绑定改回，也不会重新标成已初始化。
3. 三路原始传感器模拟 → 开始站姿引导 → 点击确认 → 新静止窗口完成；范围为 left_forearm、pelvis、head。随后仅更新前臂模拟旋转，保留 calibration_id，骨盆世界旋转保持单位四元数；其余未测量段只按层级随动。
4. 开始记录、停止保存、列表选中新会话、加载、播放、暂停、seek=1 秒、返回 LIVE。录制时绑定/重新佩戴/初始化锁定；回放时录制锁定，三个实时模拟端点仍连接，但不覆盖保存的帧。
5. 新会话 ZIP 下载包含五个版本化文件；`20261025-211210-body-5f3c29ce` 为 complete，1971 原始样本、162 个骨架帧、2 个记录事件。
6. 浏览器控制台无错误；另检查窄屏页面宽度与布局。过程快照和最后交互日志保存在代码 `.codex/scratch/body-browser` 与 `.codex/logs/body-browser-verification-20261025.txt`。
