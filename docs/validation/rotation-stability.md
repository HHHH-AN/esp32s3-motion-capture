## 从新增资料得到的结论

- 原任务书要求滤波、零偏校正、坐标转换和异常处理，但没有提供新的完整漂移算法或可直接使用的磁标定参数。原件现位于 [参考资料](../reference/README.md)。
- 根目录旧 `dashboard/fusion.py` 并不比当前版本更好：旧算法使用固定每帧修正比例，旧倾斜补偿公式也已在 CLEAN 修正。因此没有用旧源码覆盖当前算法。
- 当时 CLEAN 的单节点开发台已有静置软件陀螺零偏校准，但此前 8010 监控没有使用该能力。迁移后对应 `host/dashboard/service.py` 和 `host/run_wifi_monitor.py`。“参考姿态归零”只改变显示参考，不能消除角速度偏置。
- ICM 驱动本来就有上电自动零偏；它不检查当时是否运动，也不能保证之后残差为零。本轮新增的是每节点显式静置的**软件残余零偏**，不是首次增加芯片启动校准。
- 旧记录有明显磁场强度变化，原规范也要求磁场异常时降权。不能只因磁力计 flags 有效、数值非零，就认为磁航向可信；芯片内部 OFF_CANC 不等于整板硬铁、软铁标定。

历史双节点快照中，A 的重力和磁场首尾方向变化很小，但陀螺均值约 (3.398, -0.675, 6.682)°/s，显示姿态约 19 秒变化 15.39°，支持优先检查零偏。那次没有规定全程静止，这组历史均值没有被写入设备或作为本次校准值。

## 本轮实现

1. 每节点独立“静置校准（4秒）”：同时检查电脑时间与设备时间，至少 200 个有效样本；检查加速度、角速度波动与磁场方向变化。成功后减去该节点的三轴陀螺偏置，再进行姿态融合，并自动设置当前显示参考。失败不覆盖此前成功的偏置。
2. 校准后提供可关闭的“停稳保持”：原始加速度稳定且补偿后角速度满足连续窗口条件时，保持融合朝向；超过运动门槛立即释放。保持期间融合时钟继续前进，不会恢复运动后补积整段静止时间。它是静止假设，不是独立的精度测量。
3. 磁场强度异常、相对校准强度突变，以及磁场噪声相对水平场分量过大时，暂时跳过磁航向修正；页面显示使用状态。这样可以避免“传感器有效但航向很吵”仍不断拉动朝向。
4. 明显设备重启或换 ID 时清除旧软件偏置，要求重新校准；普通网络重连保留同设备且时钟连续的偏置。连续序号下的采样间隔异常会保留最后姿态、跳过未知间隔，不再强制把显示参考清零。间隔数量与设备时间在 API 中单独显示。

程序位于 `host/dashboard/attitude_stability.py`，只接入 `host/run_wifi_monitor.py`；原单节点开发台、位移估算和预设实验算法没有被替换。

`tests.test_attitude_stability` 与 `tests.test_wifi_monitor` 合计 36 项回归通过，覆盖独立校准、运动拒绝、90°/s 转动后停止并保持、1°/s 再次启动、关闭保持仍减零偏、设备重启/时钟回退、采样间隔保姿态，以及磁场噪声拒绝。

当前阈值是本轮工程启发式，尚不是完整传感器噪声模型：校准陀螺模长上限 10°/s，无有效磁数据时收紧为 3°/s；角速度向量标准差不超过 0.35°/s，加速度向量标准差不超过 0.01g，磁场向量相对波动不超过 5%、两端平均方向变化不超过 3°。停稳要求约 0.6 秒、至少 20 帧，角速度窗口均值模长不超过 0.12°/s，单帧超过 0.8°/s 即释放，另检查加速度波动。针对当前约 100Hz 固件验证；更低采样率需重新验证窗口的最少帧数。

磁场门槛为 50–1500mG、相对基线 0.65–1.35；校准磁场向量噪声与当前水平场分量之比超过 0.05 时跳过磁修正。这些门槛只能拒绝部分异常，无法排除所有等模长方向干扰，不能称为完整磁标定。

“显示姿态变化”包含有意的停稳保持作用，不等于传感器绝对精度、动态动作误差或长期航向精度。此轮只要求用户静置，没有进行受控的物理转动后停止试验。软件回归已模拟转动、停止、再次慢速转动，验证保持和释放；物理转动后的主观跟随效果仍需用户实际观察。

上一段静置检查只有强度保护时，A 最大显示变化约 5.17°；加入水平场噪声检查后的本段约 0.125°。这是不同时间的两段观测，不能当成有转台真值的严格误差对比。B 两段均约 0.1°。首次 A 磁噪声门槛拒绝、之后角速度波动拒绝，以及一次采样间隔触发旧初始化的记录均保留，没有覆盖失败结果。

## 使用方法

1. 保持两块板供电，电脑连接 ESP32-IMU，打开 http://127.0.0.1:8010/ 。如果页面仍是旧界面，请刷新。
2. 将板子放稳，分别点击 A、B 的“静置校准（4秒）”。看到“零偏校准完成”后再移动；失败时按提示放稳并重试。成功后已经自动设置显示参考，无需立刻再次归零。
3. 保留“停稳保持”勾选，转动后停下，观察卡片进入“停稳保持”。再次正常转动应立即恢复跟随。极慢动作测量请关闭该项，软件零偏补偿仍然有效。
4. 板子重新上电、检测到设备重启或电脑监控重启后重新校准。单纯“参考姿态归零”不替代零偏校准。温度或安装环境变化明显时也应重新静置校准。

无可信磁修正时使用六轴相对姿态，运动过程中的航向仍可能长期积累误差；停稳保持不能恢复已经丢失的真实角度。全身关节安装标定、磁硬软铁标定、多节点硬件同步和长时间动态精度尚未完成。

重复静置验证，可在确认两板持续不动之后运行：

```powershell
python -B -X utf8 tools/check_wifi_node.py --monitor-url http://127.0.0.1:8010/ --monitor-node A=192.168.4.1:9000 --monitor-node B=192.168.4.201:9000 --calibrate --seconds 12
```

工具会对同样门槛最多重试三段静置窗口，并保存拒绝结果；不要在板子运动时使用 `--calibrate`。工具不读取密码，仍有独立网络恢复守护。

`tools/check_attitude_drift.py` 另提供历史快照的离线假设重放，不补造传感器帧、不会连接硬件或把假定静止均值写入实时监控。稀疏历史快照不足以执行正式 200 帧校准，不能与上述新实板结果混同。
