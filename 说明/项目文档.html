第一次运行

先安装 Python 3.11 或更新版本，以及 PlatformIO（可使用 VS Code 扩展）。在上表选中的版本文件夹打开终端，再执行：

python -m pip install -r requirements.txt
python run_dashboard.py

浏览器打开 http://127.0.0.1:8000。一次只启动一个版本，避免默认端口被占用。板子首次使用或切换通信版本时，还需要按对应说明编译和烧录固件。

USB 基础版的默认串口是 COM21；如果你的串口不同，修改该版本 dashboard/service.py 中的 port 默认值。烧录、串口监视器和上位机不要同时占用同一个串口。

如何理解画面和数据？

  • 页面出现 14 个节点，不代表连接了 14 块实物板。
  • 数据约每秒 20 帧；当前格式没有设备时间戳、帧序号和节点编号。
  • 丢包率是按数据到达间隔估算的，轨迹也不是绝对空间定位结果。
  • 编译和软件测试通过，不代表已完成实板、无线连接或全身动作验收。

IMU-tracker firmware

ESP32-S3-MINI-1U-N4R2 motion-capture wearable-node and independent-gateway firmware, built with PlatformIO and the Arduino framework.

Safety and verification status

  • Pins follow the MINI software contract: ICM SPI/INT on GPIO8-12, LIS2MDLTR I2C on GPIO35/36, AXP2101 I2C/IRQ on GPIO33/47/48 and native USB on GPIO19/20.
  • The AXP2101 wrapper is deliberately read-only until every regulator and charging value has been measured on the final PCB. XPowersLib 0.3.3 was evaluated but its AXP2101 begin() calls disableTSPinMeasure(), a register write, so the M2 read-only gate intentionally uses a local probe instead.
  • Sensor polling is the default. MOCAP_USE_ICM_INTERRUPT=1 compiles the GPIO8 ISR -> task notification -> FIFO batch path, but must not be deployed before its polarity, packet bytes and overflow recovery pass real-board tests.
  • Sensor-to-PCB matrices are identity placeholders, clearly marked in sensor_frame.cpp; replace them only after physical axis verification.
  • No hardware acceptance result is claimed by this repository.
  • The official ST lis2mdl_reg.c/.h snapshot is not vendored yet. Select and record an exact upstream revision/license before replacing the small local read/poll wrapper; this is an explicit M3 follow-up, not a completed artifact.

Troubleshooting

No USB device

Check D-/D+ routing first. ESP32-S3 native USB is fixed to GPIO19/GPIO20. Enter ROM download mode with BOOT and EN. Try a known data cable and inspect Windows Device Manager before changing firmware.

ICM-42688-P not detected

Confirm CS is high before SPI starts, inspect 3.3 V and ground, then check SCK, MOSI and MISO on GPIO11/10/12. Reduce SPI to 1 MHz for diagnosis. Do not enable FIFO or interrupts until polling works.

LIS2MDLTR not detected

It is on its own bus: SDA GPIO35 and SCL GPIO36. Check pull-ups and scan only that bus. The PMIC uses GPIO33/GPIO47 and must not share the same TwoWire object.

AXP2101 status unavailable

Check the PMIC bus on SDA GPIO33 and SCL GPIO47. The IRQ on GPIO48 is active low. The firmware intentionally does not change regulator or charge settings.

CRC or sequence errors

Capture raw bytes before the decoder, confirm every COBS frame ends in 00, and compare against 旧版/contracts/golden. CRC16-CCITT-FALSE covers header plus payload; the two CRC bytes are appended little-endian before COBS encoding.

Wireless overload

First switch the gateway to USB to separate radio ingress from BLE egress. Check queue high-water marks, ESP-NOW receive drops, BLE notification failures and host decoder gaps independently.

帧

所有多字节整数均为小端。未编码帧为：

偏移 字段 类型 值/说明
0 magic 2 bytes ASCII MC，即 4D 43
2 version u8 1
3 message_type u8 见消息表
4 payload_length u16 仅 payload 长度
6 node_id u8 网关为 0，佩戴节点为 1..14
7 sequence u32 每个发送节点独立递增，允许回绕

标志位：

  • bit 0: accel valid
  • bit 1: gyro valid
  • bit 2: mag valid
  • bit 3: temperature valid

  • bit 6: sample queue drop since previous sample
  • bit 7: sensor bus error since previous sample
  • 其余位保留并发送为 0

Payload 首字节为 record_count，其后重复：

node_id u8
sequence u32
device_timestamp_us u64

单条记录 37 字节。网关只聚合，不修改原节点的 sequence 和 timestamp。

2.1 ICM-42688-P（SPI）

功能 ESP32-S3 GPIO 模块引脚号 ICM-42688 引脚
IMU_SCK GPIO12 16 U10.13 SCLK
IMU_MOSI GPIO11 15 U10.14 SDI
IMU_MISO GPIO13 17 U10.1 SDO
IMU_/SS GPIO10 14 U10.12 CS
IMU_INT (可选) GPIO9 13 U10.4 INT1

2.2 LIS2MDLTR（I²C，器件地址 0x1E）

功能 ESP32-S3 GPIO 模块引脚号 LIS2MDL 引脚
I²C SCL GPIO33 28 U2.1 SCL/SPC
I²C SDA GPIO34 29 U2.4 SDA/SDI/SDO
INT/DRDY (可选) GPIO47 27 U2.7 INT/DRDY

注意：LIS2MDL 使用 I²C 通信时，其 CS 引脚（U2.3）必须接高电平（VDD_IO）。“CS 悬空”是旧资料的描述；2026-09-14 导出的原理图已将 CS 接到 VDD_3V3。实际板卡是否连通仍需测量。

3. 输出数据格式

串口波特率 115200，每行一组数据（CSV 格式），约 20 Hz：

AccX(g),AccY(g),AccZ(g),GyrX(dps),GyrY(dps),GyrZ(dps),ICM温度(C),MagX(mG),MagY(mG),MagZ(mG),LIS温度(raw)
-0.0247,-0.5354,0.8613,0.669,0.637,0.349,29.14,-108.0,648.0,-16.5,-72
字段 含义 单位
AccX/Y/Z 三轴加速度 g（重力加速度）
GyrX/Y/Z 三轴角速度 °/s（度每秒）
ICM温度 ICM-42688 内部温度 °C
MagX/Y/Z 三轴磁场强度 mG（毫高斯）
LIS温度 LIS2MDL 温度传感器原始值 LSB

量程：加速度 ±8 g，陀螺仪 ±2000 °/s，磁场 ±49 gauss（1.5 mgauss/LSB）。

5. 编译与烧录

在工程根目录（platformio.ini 所在目录）执行：

# 编译
pio run

# 烧录（COM7 为示例端口，请按实际修改）
pio run -t upload --upload-port COM7

提示： - 本工程使用 ESP32-S3 内置 USB-Serial/JTAG 烧录/调试，无需外部 USB-TTL 转换器。 - 若遇到 Could not open COM7, the port is busy（设备重启循环导致端口短暂不可用），可多次重试，或按住 BOOT 键再复位后烧录。 - 查看可用串口：pio device list

6. 电脑上查看数据

  1. 用 USB 线连接板子到电脑，确认设备管理器中枚举出串口（VID 303A，PID 1001，例如 COM7）。
  2. 打开任意串口监视器，波特率选择 115200： - PlatformIO 命令：pio device monitor -p COM7 -b 115200 - 或使用 VS Code 的 Serial Monitor 插件 - 或 Arduino IDE 的串口监视器
  3. 观察数据流即可。

8. 常见问题排查

现象 可能原因 解决办法
串口无任何输出 Serial 未走 USB 串口 确认 platformio.ini 中有 -DARDUINO_USB_CDC_ON_BOOT=1
启动崩溃循环（Detected size ... smaller than the size in the binary image header(8192k)） 上传时的 Flash 容量参数与实际不符 在 platformio.ini 中同时设置 board_build.flash_size = 4MB 和 board_upload.flash_size = 4MB，再重新编译上传
打开 COM 口提示"拒绝访问/端口被占用" 有多个串口监视器进程同时打开了端口 Windows 上一个 COM 口只能被一个程序占用：关闭多余的 pio device monitor / 串口工具，只保留一个监视器；也可在任务管理器结束多余的 pio.exe / platformio.exe 进程
[ICM-42688] 初始化失败 SPI 接线错误 / 引脚映射不对 核对第 2 节引脚表
[LIS2MDL] 初始化失败 I²C 接线错误 / CS 未拉高 核对引脚表；确认 LIS2MDL 的 CS 引脚接高电平
上传时报端口繁忙 设备正在重启，端口被占用 重试多次；或按住 BOOT 再复位后烧录
磁力计数据明显偏大 附近有强磁场干扰 远离电机、扬声器等磁性物体

9. 扩展说明

  • 若更换为 8 MB Flash 的 -N8 模块：删除 platformio.ini 中的 board_build.flash_size = 4MB、board_upload.flash_size = 4MB 和 board_build.partitions = default.csv 三行（恢复为板级默认 8 MB 配置）。
  • ICM-42688 初始化时会自动执行陀螺仪零偏校准（约 1~2 秒，期间请保持板子静止）。
  • LIS2MDL 配置为连续测量模式 100 Hz，启用了偏移消除与数据块更新（BDU）。
