# 14 节点 IMU 运动可视化系统设计

## 1. 目标与范围

在现有 ESP32-S3 单 IMU 串口采集工程旁新增一套本地运动可视化系统。系统从 Windows 串口接收当前 11 列 CSV 数据，将真实 IMU 暂时映射为“右腕”节点，其余 13 个节点保持标准站立静止姿态。整体数据模型、网页和记录格式从一开始按未来 14 个真实 IMU 节点设计。

首版包含串口连接、协议解析、姿态解算、14 节点骨架、实时信号、节点状态、接收质量和数据记录。不包含账号系统、数据库、远程访问和历史回放界面。

## 2. 总体架构

```text
ESP32-S3 / COM21
        │ 当前 CSV 或未来数据包
        ▼
Python 本地服务
        ├─ 串口接收器
        ├─ 可替换协议适配器
        ├─ 姿态解算器
        ├─ 14 节点状态模型
        └─ 标准化数据记录器
        │ WebSocket + HTTP
        ▼
浏览器可视化
        ├─ 可交互人体骨架
        ├─ 实时信号曲线
        ├─ 节点状态
        └─ 接收质量与操作控件
```

Python 服务负责设备访问和数据处理，浏览器只消费稳定的标准化消息。串口协议变化被限制在协议适配器内，不应要求改动姿态、记录或页面模块。

## 3. 模块边界

### 3.1 串口接收器

- 默认串口为 `COM21`，波特率为 `115200`，允许通过启动参数或配置覆盖。
- 提供连接、断开、自动重连和读取状态。
- 为每行原始数据附加服务端单调时钟时间戳。
- 串口断开或被占用时不终止服务，而是广播明确的设备状态。

### 3.2 协议适配器

- 当前适配器解析固件输出的 11 列 CSV：三轴加速度、三轴角速度、ICM 温度、三轴磁场和 LIS 温度原始值。
- 校验列数、有限数值、合理范围和采样间隔；坏帧被计数并丢弃。
- 输出标准节点样本，不向其他模块暴露 CSV 细节。
- 未来 14 节点二进制包或文本包通过新增适配器接入。

### 3.3 姿态解算器

- 使用四元数作为内部和网络传输中的姿态表示。
- 真实右腕节点采用轻量级九轴融合：陀螺仪提供短时变化，加速度计约束俯仰和横滚，磁力计约束航向。
- 支持启动静止校准、重新归零、时间步长限制和异常样本拒绝。
- 节点安装旋转采用独立配置，避免把传感器坐标系硬编码进骨架。
- 13 个模拟节点使用固定单位或预设四元数，不运行融合算法。

### 3.4 节点状态模型

首版定义 14 个节点：腰部、头部、左肩、左肘、左腕、右肩、右肘、右腕、左髋、左膝、左踝、右髋、右膝、右踝。

每个标准节点状态包含：

- 节点 ID 和显示名称；
- 数据来源类型：`real` 或 `static_simulated`；
- 服务端时间戳和可选设备时间戳；
- 四元数；
- 三轴加速度、角速度和磁场；
- 温度；
- 在线状态、数据新鲜度和有效标记。

模拟节点必须在界面明确标为“静止模拟”，不纳入真实节点在线率和真实串口帧率统计。

### 3.5 网络接口

- HTTP 提供网页静态资源和当前配置。
- WebSocket 推送节点帧、串口状态、接收统计和记录状态。
- 浏览器可发送连接、断开、开始记录、停止记录和姿态归零命令。
- 网络消息使用版本字段，便于未来升级数据结构。

### 3.6 数据记录

- 记录标准化后的节点数据，而非仅保存当前串口原文。
- 首选 JSON Lines，每行一帧，包含格式版本和时间戳；必要时可增加 CSV 导出。
- 文件仅在用户点击“开始记录”后创建，停止记录时安全关闭。
- 解析错误、设备状态和记录失败应在网页中可见。

## 4. 页面设计

页面采用参考图的深色仪表盘视觉，自适应桌面浏览器：

- 顶栏：系统名称、接收服务状态、连接/断开、开始/停止记录、重置视角和姿态归零。
- 左上：可拖动旋转、滚轮缩放的 3D 14 节点人体骨架。真实右腕随 IMU 姿态变化，其余节点保持标准站姿。
- 右上：14 个节点卡片，显示来源、在线状态、更新频率和最后数据时间。
- 左下：节点选择器和滚动实时曲线，显示加速度模长、角速度模长、磁场模长。
- 右下：串口名称和状态、接收帧率、有效帧数、解析错误数、最新数据延迟和记录状态。

数据超时时保留最后姿态，同时将节点状态改为黄色或红色并显示超时信息。页面不得用归零数据伪装成正常测量。

## 5. 数据流

1. 串口接收器取得一行数据并记录到达时间。
2. 当前 CSV 适配器校验并生成右腕标准样本。
3. 姿态解算器更新右腕四元数；节点模型补齐 13 个静止模拟节点。
4. 记录器在启用时写入标准化帧。
5. WebSocket 将帧与统计推送到所有本地页面。
6. 页面更新骨架、曲线、节点卡片和质量指标。

## 6. 错误处理

- 串口不存在、被占用或意外断开：服务继续运行，指数退避重连并推送错误状态。
- 数据列数或数值无效：丢弃单帧，增加解析错误计数，不重启数据流。
- 时间间隔异常：限制姿态积分步长，避免一次停顿造成姿态跳变。
- 磁场异常：暂时降低或禁用航向修正，继续使用陀螺仪和加速度计。
- WebSocket 客户端断开：释放客户端资源，不影响串口读取。
- 记录写入失败：停止本次记录并报告错误，不影响实时显示。

## 7. 测试与验收

自动测试覆盖 CSV 解析、非数值和缺列数据、姿态四元数运算、时间步长限制、节点映射、模拟节点状态、记录格式和断线状态转换。浏览器端使用固定样本验证 14 节点渲染、曲线更新和状态显示。

首版验收条件：

1. 本地服务启动后可正常打开网页。
2. 连接 `COM21` 后，右腕随实际传感器转动，其他 13 个节点保持静止。
3. 右腕实时曲线连续更新，节点来源标识准确。
4. 串口断开、占用或坏帧在页面中明确告警，服务不崩溃。
5. 开始和停止记录可生成结构合法的标准化数据文件。
6. 协议解析器能够独立替换，不改变网页消息和记录格式。

## 8. 实现约束与后续扩展

- 后端采用 Python，串口通过 PySerial 接入，HTTP/WebSocket 服务采用 FastAPI。
- 前端使用浏览器原生 HTML、CSS、JavaScript，并使用 Three.js 渲染骨架；依赖应固定版本。
- 首版面向本机使用，默认只监听回环地址，不暴露到局域网。
- 后续 14 个真实节点接入时，优先增加协议适配器、节点校准与骨段约束，不更改标准节点接口。
- 历史回放、动作识别和数据库存储均属于后续独立功能。
